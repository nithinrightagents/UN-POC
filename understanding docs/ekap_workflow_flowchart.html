Core System Invariants
🙈 True Blind IndependenceRole A never reads Role B's submissions or vice versa — enforced by the query scope, not just UI hiding.
🤖 AI = Accelerator, Not a VoterHeuristic pre-fill writes agent_index=-1; shown identically to both humans as a starting suggestion only.
📖 Read/Write Splitcompute_portal_discrepancy (GET, no writes) vs recompute_portal_discrepancy (POST/seed only) — no duplicate audit rows on page refresh.
🔁 Idempotent EscalationA resubmission that leaves the same disagreement set unresolved never spawns a second queue item.
🆕 Newest-Item-Winslist_escalations orders newest-first so a re-opened dispute can never be shadowed by a stale arbitration.
🔒 Exactly-Once DispositionUNIQUE constraint on escalation_dispositions.item_id (FR-049): concurrent dispose attempts never silently overwrite.
🚫 Never Invents an Answer_final_answer() returns None rather than guessing when nobody — human or AI — ever answered.
🌐 No Export Step to Public KBPublic rankings/profile pages read PublicationRecord directly; publish IS the delivery.

Config Lane

  • seed.py threads the same Settings object through rather than hardcoding a second literal.

Stage 1 · Pre-Fill Accelerators (AI Heuristic + MSQ Evidence)
🤖
1a. AI Heuristic Pre-Fill
agent_index = -1
Portal Scan · Starting Suggestion
  • Scans the unit's resolved_url and writes one AssessorAgentRun per matched indicator, tagged agent_index=-1.
  • Shown identically to both Assessor A and Assessor B as a starting suggestion only — never a third vote.
  • Confidence below the acceptance gate is tagged below_acceptance_threshold, not hidden.
Model ID:heuristic/portal-scan-v1
Route:POST .../units/{id}/prefill
📄
1b. MSQ Document Ingestion
Member State Questionnaire PDF
  • Admin uploads a country's submitted MSQ PDF; text is extracted and stored per (cycle_id, country_id).
  • find_msq_document uses a rowid tiebreak so same-second re-uploads still resolve to the true latest.
  • Secondary evidence source for assessors alongside the live portal — never an automatic answer source.
Route:POST .../units/{id}/msq
Storage:Temp file → MSQDocument
Stage 2 · Blind Human Assessment (Assessor A / Assessor B)
🧑‍⚖️
2a. Assessor A (Blind)
Role-Scoped Reads
Independent Human Review
  • Reads only its own prior submissions via latest_human_submission(..., role=A) — never Role B's.
  • Sees the AI suggestion as a pre-filled starting point but must explicitly confirm or override it.
  • role is a typed AssessorRole enum: a garbage value is now a clean 422, not an unhandled 500.
Route:GET /assessor/{c}/{p}?role=A
Records:HumanAssessorSubmission
🧑‍⚖️
2b. Assessor B (Blind)
Role-Scoped Reads
Independent Human Review
  • Structurally identical review surface to Assessor A; zero cross-role visibility either direction.
  • Divergence from Assessor A is a genuine independent-read signal, not a UI artifact.
  • ai_suggestion_accepted is recorded on every submission for downstream audit.
Route:GET /assessor/{c}/{p}?role=B
Records:HumanAssessorSubmission
Stage 3 · Discrepancy Detection Engine
⚖️
3. Discrepancy Engine
portal_human scope
Assessor A vs B Comparison
  • differing_answer_rate = disagreements / questions both roles have answered so far.
  • Read-only compute_portal_discrepancy powers GET/display; write-path recompute_portal_discrepancy only runs from POST/seed state-changes.
  • Flags for arbitration when rate > human_discrepancy_rate_threshold (5% default).
Threshold:> 5% → flagged
Output:DiscrepancyCase
Stage 4 · Escalation Queue & Senior Reviewer Arbitration
🚨
4a. Escalation Queue
Only If Flagged
reason = PORTAL_DISCREPANCY
  • Only created when the discrepancy rate is flagged; idempotency-guarded against duplicates.
  • context carries the exact disputed question_ids, the measured rate, and compared-question count.
  • Surfaces on the admin escalations page for joint review before anything is published.
Route:GET .../{cycle_id}/escalations
Guard:unresolved_only match
👩‍⚖️
4b. Senior Reviewer Arbitration
Per-Question Disposition
Joint A/B Review
  • Records a categorical resolution PLUS an explicit arbitrated Yes/No per disputed question.
  • Dynamic resolved__<question_id> form fields read via request.form() since the dispute set varies per item.
  • FR-049: UNIQUE constraint on item_id means a second concurrent disposition fails cleanly, never overwrites.
Route:POST .../escalations/{id}/dispose
Stores:resolved_answers dict
Stage 5 · Publish — Final Answer Precedence
📤
5. Publish (One-Click)
_final_answer() Precedence Table
  • A/B agreement wins outright; on disagreement, an arbitrated resolved_answers entry overrides.
  • Still unresolved → best-effort fallback to Assessor A pending arbitration; lone submission used as-is.
  • No human input at all falls back to the AI suggestion; never invents an answer nobody gave.
Route:POST .../units/{id}/publish
Writes:PublicationRecord
